# GCS Core telemetry slice

C++14 Core receives real MAVLink telemetry over UDP, prints accepted positions
to stdout, maintains a mutex-protected latest state, and serves actual gRPC unary
and server-streaming RPCs. The existing Python simulator remains a separate,
unchanged application. No WPF or C# implementation is included.

## Build

```bash
docker build -t gcs-core:dev .
```

The multi-stage Debian 12 image compiles Linux C++14, generates Protobuf/gRPC
sources, and runs the processor/store tests before producing the runtime image.
MAVLink headers are vendored at a recorded commit; no submodule initialization
or host header directory is required. Debian packages are used for gRPC rather
than building it from source. Image/package tags can receive updates; the exact
versions verified below describe this run, not immutable future dependency pins.

## Native macOS build

CMake defaults to C++17 on macOS for modern Homebrew gRPC and retains C++14
for the Debian Docker build. The handwritten runtime still uses C++14-compatible
language features. Protobuf's config package supplies Homebrew's transitive
libraries; Debian falls back to CMake's FindProtobuf module.

```bash
brew install cmake pkg-config grpc protobuf boost
cmake -S . -B build-mac \
  -DCMAKE_PREFIX_PATH="$(brew --prefix)" \
  -DCMAKE_OSX_DEPLOYMENT_TARGET="$(sw_vers -productVersion | cut -d. -f1,2)" \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build-mac -j2
ctest --test-dir build-mac --output-on-failure
./build-mac/gcs-core
```

The deployment target matches the current Mac rather than the potentially older
SDK default. This is a local build, not a claim of compatibility with older macOS
versions. If Docker Core is running, stop it first with `docker stop gcs-core`
to free TCP port 50051. Core logs appear directly in the native terminal; Ctrl-C
shuts it down. The native process binds UDP 14550 and TCP 50051 on all interfaces,
just as the container process does; Docker's loopback port mapping does not apply
to the native process.

Run the existing simulator natively in a second terminal:

```bash
../uav-simulator/.venv/bin/python ../uav-simulator/simulator.py \
  --host 127.0.0.1 --port 14550 \
  --scenario straight --rate-hz 5 --speed-mps 5 --heading-deg 90
```

The grpcurl commands below work with native Core as well. With Core and simulator
stopped, repeat the native smoke test (starts and cleans up both processes):

```bash
python3 tests/native_smoke.py --grpcurl /private/tmp/gcs-tools/grpcurl
```

Use `--grpcurl grpcurl` if installed on PATH, or supply another executable path.
The test defaults to the adjacent simulator checkout and its `.venv/bin/python`;
`--simulator-dir` can select another checkout.

Verified on macOS 27.0.1 / Apple Silicon with Apple Clang 21.0.0, CMake 4.4.4,
Homebrew gRPC 1.85.0, Protobuf 36.2 and Boost 1.92.0_1. The native ARM64 build
completed without compiler/linker warnings when targeting macOS 27.0. Native
unit tests and the real UDP/gRPC smoke test passed: initial NOT_FOUND/WAITING,
straight-flight positions, LIVE/STALE/resume, and clean shutdown with an active
stream. The Debian C++14 Docker rebuild and its tests also passed after these
changes. The native simulator used the existing Python 3.14.6 environment.

## Run: shared Docker network (verified on this machine)

This topology works with the current macOS/Colima setup. Build the simulator
from its own adjacent checkout if its image is not already available:

```bash
docker build -t uav-sim:dev ../uav-simulator
docker network create gcs-net
docker run -d --name gcs-core --network gcs-net \
  -p 127.0.0.1:50051:50051/tcp gcs-core:dev
docker logs -f gcs-core
```

Create the network only once. In another terminal:

```bash
docker run --rm -it --name gcs-demo-sim --network gcs-net \
  uav-sim:dev --host gcs-core --port 14550 \
  --scenario straight --rate-hz 5 --speed-mps 5 --heading-deg 90
```

Use `--scenario hover` for stationary telemetry. In the simulator terminal,
`pause` stops traffic, `resume` restarts it, and `quit` exits. Core keeps its last
sample and reports STALE more than two seconds after the last valid position.
No gRPC client is needed to see telemetry:

```text
GCS Core listening UDP=0.0.0.0:14550 gRPC=0.0.0.0:50051
LINK WAITING - no valid GLOBAL_POSITION_INT yet
TELEMETRY rev=1 lat=32.0000000 lon=34.8000000 alt_msl_m=100.00 rel_alt_m=50.00 speed_mps=0.00 hdg_deg=90.00
LINK LIVE
LINK STALE - no position received for >2 seconds
```

Stop and remove Core when finished:

```bash
docker stop gcs-core
docker rm gcs-core
```

## Host-native simulator alternative

On a Docker setup supporting host UDP port forwarding:

```bash
docker run --rm --name gcs-core \
  -p 127.0.0.1:14550:14550/udp \
  -p 127.0.0.1:50051:50051/tcp gcs-core:dev
# In another terminal, using the simulator's documented Python environment:
cd ../uav-simulator
python simulator.py --host 127.0.0.1 --port 14550 \
  --scenario straight --rate-hz 5 --speed-mps 5 --heading-deg 90
```

**Local limitation:** native-host UDP forwarding did not deliver packets to Core
on the current Colima setup, even outside the command sandbox. The local native
simulator environment was Python 3.14.6. The verified shared-network topology
uses the simulator's Python 3.12 container and needs no published host UDP port.
Host TCP/gRPC forwarding worked. Docker Desktop's native-simulator topology has
not been tested here. Do not run the diagnostic UDP receiver on the same port.

## gRPC from the host

Install `grpcurl` if needed (for example with Go):

```bash
go install github.com/fullstorydev/grpcurl/cmd/grpcurl@v1.9.3
# Add Go's bin directory to PATH, then run from this project directory:
grpcurl -plaintext -import-path proto -proto telemetry.proto \
  -d '{}' localhost:50051 gcs.v1.TelemetryService/GetTelemetry

grpcurl -plaintext -emit-defaults -import-path proto -proto telemetry.proto \
  -d '{}' localhost:50051 gcs.v1.TelemetryService/SubscribeTelemetry
```

Reflection is not enabled; provide the proto file. `-emit-defaults` displays
zero values such as hover speed, revision 0, and WAITING in JSON output.

- Unary returns `NOT_FOUND` until the first accepted position, then LIVE or
  STALE with the latest values.
- A stream immediately emits WAITING, LIVE, or STALE. It polls the store every
  200 ms and emits only when revision or status changes. STALE includes the last
  sample; WAITING has no telemetry. Multiple clients have independent cursors.
- This is a latest-state stream, not packet history. Intermediate revisions or
  transitions shorter than the polling interval can be coalesced. Revisions
  increase per accepted position and reset on Core process restart.
- Ctrl-C cancels a client without stopping Core. Core shutdown signals the
  service, joins the receiver, and gives gRPC a one-second deadline to finish or
  cancel outstanding calls, including blocked writes.

The development endpoint uses insecure gRPC with host TCP published only on
loopback. The older gRPC dependency is for this local exercise; this is not a
production-secure or flight-control deployment.

## Implementation

The handwritten runtime has four classes and two small data structs:

| Files | Responsibility |
| --- | --- |
| `main.cpp` | Startup, signals, service lifecycle, bounded shutdown |
| `TelemetryGateway.h/.cpp` | One nonblocking Boost.Asio UDP receive thread, official MAVLink parser, stdout and status transition logs |
| `TelemetryProcessor.h/.cpp` | Validate coordinates/heading and convert integer MAVLink units |
| `TelemetryState.h`, `StateStore.h` | Latest state, revision, monotonic receipt timestamp, one mutex; snapshots copied out of the lock |
| `TelemetryService.h/.cpp`, `proto/telemetry.proto` | Actual synchronous gRPC snapshot and event stream |
| `CMakeLists.txt`, `Dockerfile`, `.dockerignore`, `.gitignore` | Build, generated protocol sources, container packaging |
| `third_party/` | Pinned official MAVLink generated C headers |
| `tests/core_tests.cpp` | Conversion, validation, stale retention/recovery and concurrent snapshot checks |
| `tests/integration.py`, `tests/send_frames.py` | Docker/simulator/host-grpcurl acceptance checks and repeatable malformed-frame fixture |

Only `GLOBAL_POSITION_INT` from system 1/component 1 updates state. The official
parser verifies framing/CRC and consumes bytes across datagram boundaries.
Heartbeat and attitude are ignored. Latitude/longitude outside geographic bounds
and heading >=36000 (including unknown 65535) are skipped without refreshing
liveness. Altitudes are converted from mm, north/east velocity from cm/s, heading
from centidegrees, and speed is the horizontal vector magnitude. Boot time is
not used for ordering or wall-clock time. There is no queue, history, observer
registry, logging thread, or asynchronous gRPC framework.

## Repeat the checks

```bash
# Unit tests also run automatically during docker build.
docker build --target build -t gcs-core:build .
docker run --rm gcs-core:build ctest --test-dir /src/build --output-on-failure

# Stop any Core holding host TCP 50051 before the integration test.
python3 tests/integration.py --grpcurl "$(command -v grpcurl)"
```

The acceptance script requires the two images above and Python 3 on the host.
It creates its own named containers/network, drives the unchanged simulator via
stdin, validates host grpcurl output, and cleans up its own resources. It does
not stop unrelated containers. `tests/send_frames.py` runs inside the simulator
container with its installed pymavlink; it does not modify simulator source.

During implementation grpcurl was installed from v1.9.3 in
`/private/tmp/gcs-tools/grpcurl` (the Go build reports `dev build <no version set>`).
The exact acceptance command on this host was:

```bash
python3 tests/integration.py --grpcurl /private/tmp/gcs-tools/grpcurl
```

All acceptance scenarios passed:

- No simulator: stdout WAITING, unary NOT_FOUND, one WAITING stream event with
  the subscription remaining open.
- Hover: latitude 32, longitude 34.8, MSL altitude 100 m, relative altitude 50 m,
  speed 0, heading 90; increasing revision.
- Straight: increasing longitude, 5 m/s, live events and stdout.
- Pause: one STALE transition per stream/log, retained sample, no duplicate
  unchanged events. Resume produces LIVE and newer revisions.
- Corrupt CRC, garbage, invalid coordinates/heading and foreign system/component
  IDs do not change revision. Subsequent valid frames are accepted. Two frames
  in one datagram and one frame split over two datagrams are accepted.
- Continuing valid heartbeat/attitude traffic cannot hide stale position data.
- Multiple subscribers, cancellation, zero-subscriber stdout, and reconnect.
- Simulator quit causes STALE; simulator restart resumes LIVE without boot-time
  ordering assumptions.
- `docker stop` with an active stream exits 0 without force-kill; observed 0.32 s
  in the acceptance run.

No remaining blocker for the verified shared-network Docker slice. Native-host
UDP forwarding remains unverified as described above. WPF integration, other
architectures and production hardening were not implemented or tested.
